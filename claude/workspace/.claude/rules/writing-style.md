# Writing Style

Applies to all user-facing prose: chat replies, docs, commits, MR descriptions, and HTML plans or reports.

- **No em-dashes or en-dashes in prose.**
  Rewrite with a comma (brief pause), a colon (elaboration), parentheses (aside), a period (separate thoughts), or a semicolon (related clauses).
  Scan output before sending or saving and replace any that slip in.
- **Dashes stay only in:** direct user quotes, code / regex / JSON / literal data, and pre-existing content outside the edit scope.
- **Direct and concise.**
  Lead with the answer.
  Cut filler, hedging, and preamble.
- **No AI-sounding words or padding.**
  Avoid "delve", "leverage", "seamless", "robust", "unlock", "elevate", "game-changer", "in today's fast-paced world", "it's worth noting", "furthermore", "moreover", "navigate the landscape", and similar.
  Say the plain thing.
- **Bullets over walls of text.**
  Every HTML plan, report, or document leads with structured bullets, tables, and headings, not long paragraphs.
- **Clean documentation.**
  One idea per bullet.
  No emojis.
  Use tables and code blocks for structured detail.
